# Задание 1. Анализ и планирование

### 1.1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут:
    - удалённо включать/выключать отопление в своих домах
    - настраивать температуру в доме
- Система поддерживает:
    - управление реле, которые включают или выключают отопление

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс
- Система поддерживает получение данных о температуре с датчиков, установленных в домах

**Регистрация датчиков и резе**

- Инженер выезжая к клиенту регистрирует в системе новое оборудование

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Go
- База данных: PostgreSQL
- Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- Взаимодействие: Синхронное, запросы обрабатываются последовательно.
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
- Развёртывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

- Основные домены (ключевые функции):
    - Управление отоплением (включает различные операции по включению/отключению отопления и настройки температуры)
    - Мониторинг температуры (включает в себя хранение и отображение данные о температуре с датчиков)

- Второстепенные домены:
- Подключение новых устройств (включает в себя контекст по подключению и управлению новыми устройствами)
- Управление устройствами партнеров (различные интеграции с устройствами диллеров/ сторонних производителей. Включает в себя контекст для интеграции устройств партнёров)

- Общедоступные домены:
    - Уведомления (отправка уведомлений пользователям. Включает контекст уведомлений для обработки различных событий для уведомления пользователей системы)
    - Пользовательский интерфейс (авторизация, управление личным кабинетом, управление учётными записями)

### **4. Проблемы монолитного решения**

- Для подключения устройства необходим выезд специалиста
- Отсутствие асинхронности
- Сложно адаптировать под новые функции или требования
- Отсутствие масштабируемости
- Добавление новых модулей нельзя быстро добавить

# Задание 2. Проектирование микросервисной архитектуры

**Управление оборудованием:**

- Пользователи могут:
    - удалённо включать/выключать отопление в своих домах
    - настраивать температуру в доме
    - удаленно включать/выключать свет
    - открывать ворота
    - контролировать данные с камер
- Система поддерживает:
    - управление реле, которые включают или выключают отопление
    - регистрацию устройств по популярным протоколам Zigbee, Wi-Fi, Thread
    - автоматизацию управления оборудования на основе заранее сохраненных сценариев
    - отправку уведомлений на почту или в телеграм

**Мониторинг оборудования:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс
- Система поддерживает получение данных о температуре с датчиков, установленных в домах
- Проверять текущее состояние выключателей
- Проверять текущее состояние ворот (открыты/закрыты)
